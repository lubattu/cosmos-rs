# Introduction

COSMOS — Continuous Subspace Manifold Operating System — is a learning
framework in which every learnable quantity is an orthonormal subspace
basis, and learning is gauge dynamics on the Grassmannian rather than
Euclidean descent on weights.

`cosmos-rs` is the reference implementation. It is a Rust library with no
external numerical dependency: the decompositions, the matrix exponential,
the retractions and the geodesic distances are all in the crate. It
computes on the CPU in `f64`, and it is accompanied by a driver that
reproduces every experiment reported in the article that describes the
framework.

## What is different here

In a conventional network a layer owns a weight matrix, the loss produces a
gradient with respect to that matrix, and an optimizer moves the matrix in
the ambient space. Whatever structure the matrix was supposed to have —
orthogonality, a bounded condition number, a fixed rank — is at best
encouraged by a penalty and is never guaranteed.

COSMOS turns that around. The learnable objects are frames: matrices with
orthonormal columns, each spanning a subspace. Updates are not steps in the
ambient space; they are the action of an orthogonal transformation
generated by an antisymmetric connection. An orthogonal transformation maps
an orthonormal frame to an orthonormal frame, so the invariant is preserved
by construction rather than by a penalty, to the precision of the
arithmetic. The library's integration tests hold that residual to the
numerical floor across a full training run.

The consequence is that "what the model knows" and "how the model changes"
are two different kinds of thing. The first is a point on a product of
Grassmannians. The second is a flow on that manifold. Everything else in
this book follows from keeping those two separated.

## Scope

The library implements the model family the article reports: flat and
patch-wise classifiers, the geodesic class-manifold-region readout, gauge
dynamics, and four interior topologies. A module, feature or configuration
option belongs in the crate when a table, figure or prose number of a
publication depends on it. Everything else is out of scope until it has
been measured in public.

The crate is `f64` on the CPU. The default feature set is pure Rust; an
optional `lapack` feature delegates the dense decompositions to a generic
BLAS/LAPACK. Hardware acceleration is out of scope, and the dependency
audit bans external machine-learning framework crates outright.

What is planned beyond this scope, and in which order, is stated in the
repository's `ROADMAP.md`.
